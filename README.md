# Darwin-GRC-GDPR-Privacy-Compliance-Assessment

## Project Overview

This project simulates a GDPR privacy and data protection compliance assessment for a fictional SaaS organization called **CloudNova Technologies**.

The goal is to evaluate how personal data is collected, processed, stored, shared, retained, and protected, while identifying privacy risks, control gaps, and remediation priorities.

This project demonstrates practical GRC and privacy skills including:

- GDPR compliance
- Privacy governance
- Personal data inventory
- Lawful basis review
- Data minimization
- Data retention
- Data subject rights
- Third-party privacy risk
- Privacy gap analysis
- Privacy risk assessment
- Breach response
- Remediation planning

## Business Scenario

CloudNova Technologies is a fictional SaaS company that provides cloud-based services to customers in multiple regions.

The organization processes personal data including:

- Customer names
- Email addresses
- Account information
- Billing information
- Support tickets
- Employee information
- IP addresses
- Usage data
- Vendor contacts
- Marketing preferences

Because personal data may relate to individuals in the European Economic Area, the organization must evaluate its privacy practices against GDPR requirements.

## GDPR Principles Reviewed

### Lawfulness, Fairness, and Transparency

Personal data should be processed lawfully, fairly, and transparently.

### Purpose Limitation

Personal data should only be used for specified and legitimate purposes.

### Data Minimization

Organizations should only collect personal data that is necessary.

### Accuracy

Personal data should be kept accurate and up to date.

### Storage Limitation

Personal data should not be retained longer than necessary.

### Integrity and Confidentiality

Appropriate security controls should protect personal data.

### Accountability

Organizations should be able to demonstrate compliance with privacy requirements.

## Example Finding

### Data Retention

**Current State:**  
Retention practices exist, but retention periods are not consistently documented across systems.

**Risk:**  
Personal data may be retained longer than necessary.

**Risk Level:**  
High

**Recommendation:**  
Create a formal retention schedule defining retention periods, deletion triggers, data owners, and evidence of secure deletion.

1. Complete the personal data inventory
2. Formalize Records of Processing Activities
3. Document lawful basis for each processing activity
4. Establish a formal retention schedule
5. Improve data subject request tracking
6. Strengthen processor due diligence
7. Document international transfer safeguards
8. Conduct recurring privacy impact assessments
9. Test privacy breach-response procedures
